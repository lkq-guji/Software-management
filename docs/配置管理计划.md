# 教学工作量管理系统配置管理计划（组长维护）

## 配置管理目标
保证需求、代码、测试、项目数据、记录均有唯一版本，所有变更可追踪，并通过 GitHub Pull Request 完成组员并发协作、修改控制及版本发布。

## 配置项基线
- CI-01: `README.md`、`docs/需求说明.md`（需求/说明）
- CI-02: `app.py`、`workload.py`（源代码）
- CI-03: `tests/`（测试代码）
- CI-04: `data/workload.csv`（虚拟数据）
- CI-05: `docs/配置管理计划.md`、`docs/变更记录.md`（配置与变更记录）

## 角色与分支
- 组长：`docs/leader-release`；管理仓库、变更审核、整合、版本发布。
- 组员A：`docs/requirements`；完善需求与配置项清单。
- 组员B：`feature/course-statistics`；扩展按课程统计功能。
- 组员C：`test/coverage-ci`；完善边界测试与自动化检查。

## 工作流（四人小组）
`main` 为稳定基线；成员从 `main` 新建分支，提交实际改动后推送到同名远程分支，发起 PR 到 `main`。PR 说明须包含修改内容、验证命令、影响和截图；组长审查测试结果并决定是否合并。不得强推或覆盖成员的提交历史。

## 变更控制与版本
变更申请 → 分析 → 个人分支实现 → 测试 → PR → 组长审核 → 合并 → 更新变更记录 → 标签发布。首次团队完整发布后由组长创建注释标签 `v1.0.0`；所有成员先共同确认测试通过。

## 注意事项
代码仓库为公开仓库，不上传小组成员学号、姓名、个人实验报告或机密数据。提交作者必须是各成员本人；不伪造他人记录。
